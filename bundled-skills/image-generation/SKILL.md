# Image Generation

这是一个**全局图片生成执行 skill**。目标是把“生成图片”这件事做成稳定、可复用、可路由的能力，而不是每次临时拼请求。

## 何时触发

遇到以下请求，优先使用本 skill：
- 生成图片 / 帮我画图 / 出一张图
- 海报、封面、banner、KV、信息图、插画、配图、概念图、UI 视觉稿
- 社交媒体图片、小红书封面、公众号首图、短视频封面
- 明确提到图像模型：`3.1`、`gemini-3.1-flash-image`、`flash-image`、`pro-image`
- 用户说“再来一版”“迭代一版”“换个风格/比例/构图/配色”且对象仍是图片

如果请求本质上是：
- **要写代码接入图片生成功能** → 优先 `agile-codex`
- **要用浏览器登录第三方站点手工出图** → 优先 `browser-docker-use`
- **已经有图片文件，只是要发到飞书** → 在 Feishu 场景优先 `feishu-media-send`

## 默认执行策略

### 1) 先判断是否真的是“生成图片”

命中这类意图时，不要把它误路由成普通聊天、网页搜索或编码任务。

### 2) 优先使用本机稳定图像生成链路

在当前环境，优先复用**本机已验证可用**的 Flow2API / Gemini 图像生成入口，而不是临时换一套链路。

默认优先级：
1. 本机可用的 Flow2API 图像模型链路
2. 已知可用的 OpenAI-compatible 图像接口
3. 如果必须登录/验证码/网页交互，才转 `browser-docker-use`

### 3) 模型选择规则

当用户明确指定模型时，优先满足：
- 说“用 3.1 的模型” → 优先 `gemini-3.1-flash-image-*`
- 说“用 pro image” → 优先 `gemini-3.0-pro-image-*` 或当前环境可用的 pro-image 族

当用户没有指定模型时：
- 通用快速出图：优先 `gemini-3.1-flash-image-*`
- 更重视质感/更高要求：可考虑 `pro-image` 族

### 4) 比例/构图选择规则

优先尊重用户比例；如果后端没有完全同名比例，选择**最接近的模型**，并把真实需求写进提示词中补偿。

建议映射：
- `1:1` → `square`
- `16:9` / 横版封面 → `landscape`
- `9:16` / 竖版海报 → `portrait`
- `4:3` → `four-three`
- `3:4` → `three-four`
- `4:5`：如果没有原生 `4:5`，优先选**最接近的竖版模型**（通常 `three-four`），并在 prompt 中明确要求“接近 4:5 社交媒体封面视觉比例”

不要为了“严格匹配字面比例”而乱选明显不合适的模型。

### 5) 提示词处理规则

生成前要把用户原始意图整理成一版**适合图像模型执行**的 prompt：
- 保留主题、风格、配色、主体元素、文字要求、版式要求
- 保留输出用途：海报/封面/信息图/社媒图
- 对中文信息图，要明确：
  - 中文排版清晰
  - 标题突出
  - 卡片结构明确
  - 留白和层级清楚
  - 不要过度写实照片感（如果用户要设计稿感）
- 如有禁忌也要写明：
  - 不要杂乱
  - 不要低质 AI 感
  - 不要错误英文占位符

### 6) 生成结果交付规则

- 如果返回的是**可直接访问的稳定 URL**，可以直接交付链接
- 如果返回的是 **data URL / base64**，优先落地成文件
- 在 **Feishu** 场景，如果已经拿到了本地图片文件，优先交给 `feishu-media-send` 思路处理，尽量把图片直接发到当前会话，而不是只发服务器路径
- 如果暂时只有外链，也可以先把链接交付给用户，再视需要补发飞书原生图片

### 7) 失败处理

常见失败分类：
- 认证失败 / API key 错误
- 外层网关/CDN 拦截（例如域名 403）
- 生成超时
- 返回不是图片而是文本错误
- 比例或模型名不支持

处理原则：
1. 先换**更稳定的入口**（例如从外部域名改走本机入口）
2. 再检查模型名、比例映射、鉴权
3. 仍失败时，给出清晰失败原因，不要假装成功

## 推荐实现方式

优先使用 skill 自带脚本统一发请求，不要每次临时拼 curl/python。

- 入口脚本：`{baseDir}/scripts/generate_via_flow2api.py`
- 当需要看支持模型时，可先调用脚本的 `--list-models`
- 当需要实际生成时，传入：
  - base URL
  - API key
  - 模型名
  - prompt
  - 输出路径

## Feishu 场景补充

如果当前就是 Feishu 对话，且你已经成功拿到本地图片文件：
- 优先让用户在会话里直接看到图片
- 参考 `feishu-media-send` 的发送原则
- 不要只丢一个很长的内部路径

## 输出风格

- 成功时：直接给结果
- 如果做了比例折中：简短说明一句就够
- 如果支持继续迭代：告诉用户可以继续改一版，但别啰嗦

## 目标

让“生成图片”成为一个：
- **能被准确命中** 的全局能力
- **有稳定默认链路** 的执行能力
- **能在宿主和租户都继承** 的安装能力
- **能和 Feishu / using-superpowers 正确协作** 的路由能力
